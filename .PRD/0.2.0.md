# 0.2.0

## 剥离契约锁 / 运输合同 / 中介撮合协议 / 入驻协议 阅读与签署逻辑

> 类型：优化升级（功能解耦移除）

### 概述

平台早期接入了"契约锁电子签授权 + 运输合同阅读 + 中介撮合协议阅读 + 入驻协议签署"四大合同/协议子系统，作为发布货源与订单签署的前置/查看能力。现业务决定**整体下线这四项能力，并采用直接删除代码的方式彻底剥离**（目录、组件、配置、引用一律移除，编译零残留）。

由于四项能力被全部剥离，「发布货源」前置流程不再包含任何合同/协议类校验，仅保留业务侧的 precheck（货主认证 + 装卸货地址）。原负责编排"precheck + 契约锁 + 入驻协议"的 `usePublishFlow` 随之退化为仅 precheck，按"直接删除"原则一并移除，由首页直接调用 `panel.precheck()` 承接。

### 数据模型 Schema

#### 发布前置流程（收敛后）

| 字段 | 原类型 | 说明 |
|------|------|------|
| precheck（货主认证 + 装卸货地址） | function | **保留**：业务侧前置校验，由 `panel.precheck()` 直接调用，不再经 `usePublishFlow` 编排 |
| contractAuth / entrySign | object | **删除**：契约锁授权、入驻协议签署状态钩子，随能力剥离移除 |
| PUBLISH_FLOW_REASON（CONTRACT_* / ENTRY_SIGN_*） | enum | **删除**：相应 reason 常量随 `usePublishFlow` 移除 |

#### 协议业务编码常量（收敛后）

| 字段 | 原类型 | 说明 |
|------|------|------|
| PROTOCOL_CODE（FARMER_ENTRY / TRANSPORT_CONTRACT / AGENT_MATCHMAKING / …） | object | **删除**：随 `useProtocol` / `useEntrySign` 目录整体移除，不再保留任何协议编码常量 |
| ApiResolveContractTemplate / ApiGetContractReadStatus / ApiSubmitContractRead / ApiGetEntrySignStatus / ApiCreateEntrySign | function | **删除**：对应 service 随目录移除 |

### 页面交互

- 设置页（pages_login/setting）：菜单项由「关于我们 / 隐私政策 / 服务协议 / 入驻协议 / 运输合同 / 中介撮合协议 / 契约锁授权 / 修改密码 / 注销账号」收敛为「关于我们 / 隐私政策 / 服务协议 / 修改密码 / 注销账号」，不再展示任何合同/协议类入口与状态
- 首页"快速发布"：前置校验由"precheck → 契约锁授权 → 入驻协议签署"变为"仅 precheck（货主认证 + 装卸货地址）"；不再弹 `ModalContractAuth` / `ModalJoinSign`
- 契约锁授权页 / 运输合同阅读页 / 中介撮合协议阅读页 / 入驻协议签署页：相关导航入口全部移除（`pages_protocol/*` 页面 `.vue` 当前本就未落地，剥离后无新增死链）
- 小程序插件：`qyssdk-plugin` 声明移除，微信端不再具备契约锁插件跳转能力

### 扩展性要求

- **合同/协议能力整体解耦**：本次将四类能力一次性删除，后续若重新引入签署/阅读能力，应新建独立 hook（签署类复用统一的模版 resolve 接口，阅读类独立实现），避免再次出现 `useProtocol` / `useEntrySign` 共用 `ApiResolveContractTemplate` 却分两目录的耦合
- **发布流程极简**：发布仅依赖业务 precheck，不再耦合任何合同/协议状态；新增发布前置规则应直接扩展 `panel.precheck()`，不回流到已删除的 `usePublishFlow`
