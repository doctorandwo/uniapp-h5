# 0.4.0

## 首页推荐运力列表接入真实接口

> 类型：新增

### 概述

首页「推荐运力」列表（`src/pages/home/components/ListPanel/index.vue`）当前使用 mock 数据（`ApiPageRecommendedDispatcherList` → `getRecommendedDispatcherListMock`），卡片为团队维度样式。

本次切换为真实接口 `/driver/recommend/list`（司机维度），卡片按原型图渲染司机维度数据；新增「货主常用路线」前置查询（`/driver/recommend/commonRoute/{shipmentCode}`）返回的装卸货城市编码，作为列表接口筛选参数；`authStatus` 固定为 `3`（审核通过）。详情点击本期仅保留空壳事件，不跳转。

涉及 `ServiceCard` 为「首页」与 `publishSuccess` 页共用组件，本次直接改造该组件，已知会影响 `publishSuccess` 页卡片视觉（已与用户确认接受），并加向后兼容保护避免 mock 数据报错。

### 数据模型 Schema

#### RecommendDriverListQuery（列表查询参数）

| 字段 | 控件 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|------|--------|------|
| pageNum | 隐藏（分页内部维护） | number | 是 | 1 | 页码，触底 +1，刷新重置为 1 |
| pageSize | 隐藏（常量） | number | 是 | 10 | 每页条数 |
| authStatus | 隐藏 | number | 是 | 3 | 司机审核状态，固定 3（审核通过）；不传审核时间 |
| loadCityCode | 隐藏（取自常用路线） | string | 否 | '' | 常用路线装货城市编码，取 `commonRoute` 第一条 |
| unloadCityCode | 隐藏（取自常用路线） | string | 否 | '' | 常用路线卸货城市编码，取 `commonRoute` 第一条 |

#### CommonRouteQuery（货主常用路线查询）

| 字段 | 控件 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|------|--------|------|
| shipmentCode | 隐藏（store getter） | string | 是 | `store.getters.shipmentInfo.code` | 货主编码，路径变量 |

#### DriverCardItem（列表卡片展示模型）

| 字段 | 控件 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|------|--------|------|
| driverName | 文本（卡片标题） | string | 否 | '' | 司机姓名 |
| recommendRate | 文本（绿色百分比） | number | 否 | 0 | 推荐度 0-100，展示 `xx% 推荐` |
| vehicleImage | 图片（左图） | string | 否 | 默认图 | 取 `availableVehicles[0].vehicleImage` |
| availableVehicles | 图片+文本列表 | array | 否 | [] | 车辆聚合；每项为 `{ vehicleCode, licenseNumber, vehicleImage, vehicleLength, vehicleTypeCode, vehicleLoadWeight }`；车辆行为空时隐藏 |
| loadCityName / unloadCityName | 文本（线路行） | string | 否 | '' | 装/卸货城市 |
| sameRouteWaybillCount | 文本（线路行·趟数） | number | 否 | 0 | 相同线路运输趟数，展示 `· N趟` |
| cooperationCount | 浮层标签 | number | 否 | 0 | 与当前货主合作次数，0 时不显示 |
| fulfilledWaybillCount | 标签 | number | 否 | undefined | 履约运单数（后端补字段），展示 `履约 N 单`；undefined 隐藏 |
| onTimeRate | 标签 | number | 否 | undefined | 准时率 0-100，展示 `准时率 N%`；undefined 隐藏 |

### 页面交互

- 进入首页加载列表：先取货主编码 → 查常用路线（取第一条的装卸货城市编码）→ 带 `authStatus=3` 与城市编码请求列表，触底自动加载下一页，无更多时展示「没有更多了」，请求中展示 loading 防重触发
- 卡片布局：左图为车辆图片（左下角浮层「合作过 N 次」），右侧为司机名 + 绿色推荐度，其下「车辆」行（多车 `/` 拼接）、「线路」行，底部仅 2 个标签（履约、准时率）
- 点击卡片触发 `$emit('detail', info)`，本期不跳转，事件供后续详情页接入
- 列表为空展示 `@/components/Empty`

### 扩展性要求

- **接口单一收口**：推荐运力相关接口统一放 `src/pages/home/services.js`，后续新增字段（如 `availableVehicles` 补 `vehicleTypeName`、列表补 `fulfilledWaybillCount`）只改 ServiceCard 映射与 service，页面零感知
- **字典缓存复用**：`vehicleLength` / `vehicleClassification` 字典经 `getDicts` 加载后缓存；若后续列表接口直接返回车型名，可移除映射逻辑，不影响卡片结构
- **向后兼容保护**：ServiceCard 对 `availableVehicles`、`fulfilledWaybillCount`、`onTimeRate` 等缺失字段做隐藏/兜底，避免 `publishSuccess` 页 mock 数据渲染报错
- **跨端安全**：父组件只向子组件下发可序列化数据，卡片点击以 `$emit('detail', info)` 上抛纯数据，不传函数（遵守 `docs/agent/rules-mp.md`）

### 已确认决策

1. **履约标签数据来源**：列表接口无 `fulfilledWaybillCount`，确认由后端补此字段到列表接口返回；本期卡片使用 `fulfilledWaybillCount` 展示「履约 N 单」
2. **车辆行展示**：列表接口返回聚合字段 `availableVehicles[]`（含 `vehicleTypeCode`），多车以 `/` 拼接展示，如 `13米高栏 31吨 / 17米平板 32吨`
3. **组件改造方式**：直接改造共用的 `ServiceCard`，接受 `publishSuccess` 页卡片视觉随之变化，并做向后兼容保护
4. **详情处理**：本期只保留 `$emit('detail')` 空壳事件，不实现详情页；顺带新增 `commonRoute` 前置查询驱动列表筛选
5. **筛选参数固定值**：`authStatus` 固定为 `3`，不传审核时间；装卸货城市编码取 `commonRoute` 返回数组第一条
6. **货主编码来源**：`this.$store.getters.shipmentInfo?.code`
7. **车型名称映射**：用 `getDicts('vehicleLength')`、`getDicts('vehicleClassification')` 返回字典列表匹配组装车长/车型名称（code→label）
