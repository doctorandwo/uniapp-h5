# 0.3.0

## 常用地址管理（地址簿）

> 类型：新增

### 概述

当前项目只有「保存常用地址」能力（发布货源 / 公共选点页在勾选后落库），**没有面向用户的地址簿管理界面**：用户无法查看、编辑、删除已保存的常用地址，「我的-地址簿」快捷菜单（`src/pages/user/components/QuickMenu.vue`）的点击目前是 `console.log` 占位，统计接口返回的 `addressCount` 也无落地页承接。

本次新增「常用地址管理」模块：以 `/assets/shipment/address-app/*` 系列接口（list / add / edit / remove）为数据底座，落地 **2 个页面**——列表页与新增/编辑页（同一页面按 `id` 区分），统一使用 `@/components/SubPageLayout` 三段骨架，补齐常用地址的**增、删、改、查**全链路，并接入「我的-地址簿」入口。

同时按用户要求，常用地址相关接口**整体切换到 `-app` 系列**（`list` 与 `add` 一并切换），并把散落在 `pages_common/chooseLocation` 与 `pages_goodsSource/sourcePublish` 的两份重复 `commonAddressHelper.js` 收敛到一处。

新增页面统一放到新建的 `pages_user` 分包，并集中在一个业务目录 `addressBook/` 下。

### 数据模型 Schema

#### AddressListQuery（列表查询参数）

| 字段 | 控件 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|------|--------|------|
| pageNum | 隐藏（分页内部维护） | number | 是 | 1 | 页码，触底 +1，搜索/刷新重置为 1 |
| pageSize | 隐藏（常量） | number | 是 | 10 | 每页条数，取自 `constants.js` PAGE_SIZE |
| addressAlias | 顶部搜索框 | string | 否 | '' | 地址别名，模糊匹配；与 `addressName` 共用同一关键词 |
| addressName | 顶部搜索框 | string | 否 | '' | 地址名称，模糊匹配；与 `addressAlias` 共用同一关键词 |

#### AddressCardItem（列表卡片展示模型）

| 字段 | 控件 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|------|--------|------|
| id | 隐藏（操作主键） | number | 是 | - | 主键，编辑/删除时使用 |
| addressAlias | 文本（卡片标题） | string | 是 | '' | 地址别名 |
| detailText | 文本 | string | 否 | '' | 详细地址，取 `formattedAddress`，为空时回退 `省+市+区+addressName` 拼接 |
| contact | 文本 | string | 否 | '' | 联系人 |
| contactPhone | 文本 | string | 否 | '' | 联系电话 |
| addressType | 标签 | number | 是 | - | 1 装货 / 2 卸货，映射为彩色标签文案 |
| addressName | 文本 | string | 否 | '' | 地址名称，参与 `detailText` 回退拼接 |
| province / city / district | 隐藏 | string | 否 | '' | 省市区名称，编辑时回填 |
| provinceCode / cityCode / districtCode | 隐藏 | string | 否 | '' | 省市区编码，编辑时回填 |
| longitude / latitude | 隐藏 | string | 否 | '' | 经纬度，编辑时回填 |

#### AddressForm（新增/编辑表单模型）

| 字段 | 控件 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|------|--------|------|
| id | 隐藏 | number | 否（新增）/ 是（编辑） | - | 主键，仅 `PUT` 时提交 |
| addressName | 地址选择（点击跳转地图选点回填，只读展示） | string | 是 | '' | 地址；由选点页带回 POI 名称、省市区与经纬度 |
| detail | 多行文本输入 | string | 否 | '' | 详细地址，门牌号等补充信息 |
| addressAlias | 单行文本输入 | string | 是 | '' | 地址别名，卡片标题 |
| contact | 单行文本输入 | string | 是 | '' | 联系人 |
| contactPhone | 数字输入（手机号） | string | 是 | '' | 联系电话，11 位手机号格式校验 |
| addressType | picker | number | 是 | 1 | 1 装货 / 2 卸货，提交为 integer |
| province / city / district | 隐藏（选点回填） | string | 否 | '' | 省市区名称 |
| provinceCode / cityCode / districtCode | 隐藏（选点回填） | string | 否 | '' | 省市区编码，沿用 `toShortProvinceCode` 等短码工具 |
| longitude / latitude | 隐藏（选点回填） | string | 否 | '' | 经纬度 |
| shipmentCode | 隐藏 | string | 否 | 当前货主编码 | 与现有 `buildCommonAddressPayload` 保持一致 |
| status | 隐藏 | number | 否 | 1 | 仅 `PUT` 提交，沿用原记录状态（1 启用 / 2 禁用），缺省 1 |

### 页面交互

- 列表页顶部为搜索区（输入框 + 搜索按钮），输入为空时展示全部；点击搜索或清空均重置分页并重新请求；搜索仅匹配地址别名与地址名称
- 列表项采用卡片样式：白底圆角、上下排列「地址别名（标题）+ 详细地址 + 联系人 / 联系电话」，右上角为地址类型标签（装货 / 卸货），卡片底部为「编辑 / 删除」操作区
- 触底自动加载下一页；已加载全部时展示「没有更多了」；请求中展示 loading，避免重复触发
- 下拉刷新重置列表；新增/编辑/删除成功后列表页同步刷新，并把「我的」页 `addressCount` 一并刷新（返回时触发 `onShow` 重新拉取）
- 删除前必须二次确认弹窗，确认后删除；删除失败 toast 提示错误原因，不改动列表数据
- 点击底部「+ 新增地址」进入新增页；点击卡片「编辑」进入编辑页（同一页面，`id` 为空即新增模式）
- 「地址」项点击后跳转公共地图选点页，选中即回填地址名称、详细地址、省市区与经纬度；选点过程不写入常用地址
- 地址类型点击后弹出 picker，选中即回填展示文案与提交值
- 表单保存时逐项校验：必填项缺失、手机号格式错误时 toast 提示；校验通过按钮进入 loading 防重复提交
- 保存成功后 toast「保存成功」，返回列表页并刷新
- 页面返回走 `SubPageLayout` 的 `hasBack`，不额外实现自定义返回；编辑页不做未保存改动拦截

### 扩展性要求

- **接口单一收口**：地址相关接口统一放 `addressBook/service.js`，后续新增字段（如默认装/卸货地址 `defaultPut`/`defaultPush`、启用禁用 `status`）只改 `model.js` 的 payload 构造，页面零感知
- **地址类型枚举化**：`ADDRESS_TYPE` 与 `ADDRESS_TYPE_OPTIONS` 集中在 `constants.js`，picker 选项与标签文案同源，新增类型（如自装/自卸）只需扩展常量
- **复用既有能力**：列表分页沿用页面内 `pageNum/pageSize + scrolltolower` 模式（项目暂无通用 `useList`）；确认弹窗复用 `@/common/platform/modal.js` 的 `showModal`；空态复用 `@/components/Empty`；地图选点复用公共页 `/pages_common/chooseLocation/index`
- **跨端安全**：父组件只向子组件下发可序列化数据，卡片操作以 `$emit('action', { id, action })` 上抛，不传函数（遵守 `docs/agent/rules-mp.md`）
- **后续可扩展**：本版不做默认地址设置与启用/禁用，接口已具备 `defaultPut`/`defaultPush`/`status` 字段，预留为下一版增量面

### 已确认决策

1. **接口替换范围**：常用地址接口整体切到 `-app` 系列（`list` 与 `add` 一并切换），现有发布货源与公共选点保存链路同步生效
2. **搜索范围**：仅匹配「地址别名 + 地址名称」，不匹配联系人与联系电话
3. **「地址」字段录入方式**：跳转公共地图选点页回填（省市区 + 经纬度 + 地址名称 + 详细地址），选点页以 `pickOnly` 模式运行，不触发保存
4. **列表筛选**：仅顶部关键词搜索，不做地址类型筛选
5. **编辑页返回拦截**：不做未保存改动拦截
6. **详细地址展示**：取 `formattedAddress`，为空时回退 `省 + 市 + 区 + addressName` 拼接

### 用户故事

1. 作为货主用户，我在「我的」页点击地址簿，能看到我已保存的全部常用地址，并看到数量与统计一致
2. 作为货主用户，我输入关键词搜索，能快速定位到目标地址
3. 作为货主用户，我点击「+ 新增地址」填写地址、详细地址、别名、联系人、电话并选择装货/卸货类型，保存后能在列表中看到新地址
4. 作为货主用户，我发现地址信息有误时，点击卡片「编辑」修改后保存，列表立即更新
5. 作为货主用户，我不再使用某个地址时，点击「删除」并在确认弹窗中确认，地址被移除且列表刷新
6. 作为开发者，地址相关接口与地址模型集中在一处，后续新增默认地址、启用禁用等字段时改动面最小
